# Dota 2 1×1: отдельный тест с другом — 01.11.2026

Разрешение владельца: создать баннер, тестовый Dota 2 1×1 турнир и тестовую команду в Preview; проверить вход и работоспособность. Main/Production/финансы/SMTP/ключи/миграции не входят в разрешение.

## Подготовленные записи
- Турнир: DEAFHUB TEST · Dota 2 1×1; игра dota2; roster_size=1; бесплатный технический тест, без призов/оплат/заявления о настоящих результатах.
- Команда: DEAFHUB TEST SOLO A; один капитан-игрок. Для второго участника — отдельный состав из одного игрока, без включения обоих соперников в одну команду.
- Регламент: тест обычного матча Solo Mid 1×1; все участники подтверждают регламент; результаты записываются только после фактического теста, искусственный результат не выдаётся за сыгранный матч.
- Начало: при публикации выбрать будущую дату, минимум через 24 часа. Для дружеского QA дату согласовать с владельцем до реального матча. Баннер: собственная иллюстрация, оригинальный игровой логотип и HTML-текст поверх, с явной пометкой TEST.

## Подтверждено чтением Preview
- /sign-in: кнопка «Войти через Steam» включена после проверки готовности. Свежий вход другим человеком пока не подтверждён.
- Email signup: существующая конфигурация разрешает отправку писем только одобренным адресам. SMTP/подтверждение email не отключать и не обходить.
- У текущей сессии не показаны роль организатора и форма создания турнира. Новые записи не создавать напрямую через SQL в обход этого ограничения.
- Два существующих события «1x1 solo mid» имеют roster_size=2; их не менять и не считать новым правильным QA 1×1.

## Обязательная зависимость
Для hosted-создания нужен организатор. Минимальный отдельный вариант: временная роль организатора для уже созданного одноразового QA-аккаунта организатора из remaining-e2e-plan.md. Нужна отдельная явная отмена прежнего запрета на облачное изменение ролей именно для этой временной QA-роли. Реальный аккаунт владельца не менять. После теста удалить только созданные в этом тесте записи и временную QA-роль по сохранённым UUID; чужие записи не затрагивать. Изменение ролей/очистку не выполнять до подтверждения.
