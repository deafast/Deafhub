## Поведение

Профиль → История: собственные подтверждённые матчи по зарегистрированному snapshot-составу. Отдельный GET /api/match-history, 20 записей и курсор следующей страницы. Курсор сохраняет микросекунды PostgreSQL и уникальный ключ при одинаковой дате. Сортировка использует время подтверждения, при его отсутствии дату расписания/турнира с точной подписью. Время окончания игры не выдумывается. BYE/ожидающие/пропущенные матчи не включаются. Технический результат не трактуется как поражение текущего игрока.

RPC hub_player_match_history проверяет auth.uid(), не принимает чужой user_id; возвращает только собственные матчи. SECURITY DEFINER с пустым search_path нужен для минимальной даты из закрытого организаторского аудита: команды/акторы аудита клиенту не выдаются. anon execute запрещён. Private/no-store у HTTP-ответа. Прямой переход на турнир использует точный серверный фильтр, а не первые 500 глобальных записей. При смене пользователя состояние профиля сбрасывается.

Hosted-миграция 20261021111817_player_match_history применена. Старые даты не backfill; новые ручные finished-результаты получают серверное confirmed_at, повторная запись не позволяет подделать дату. Для движка используется аудит последней ревизии, а не MAX(created_at).
